| Слой | Состояние |

| Ядро (агрегатор, lifecycle, персистентность, конкурентность) | ✅ отлично, race-детектор чистый |

Система **работает** в штатном режиме (прогон 90 сек: 444 500 тиков, 0 ошибок БД, graceful shutdown), но **собирает данные только с 2 из 8 бирж**. Причины — не в ядре, а в том, что биржи молча поменяли API. Это главный результат аудита: smoke-инструмент (`cmd/smoke`) + метрики `screener_ticks_total{exchange}` / `screener_funding_age_seconds{exchange}` теперь делают такие поломки **видимыми за минуты, а не месяцы**.

## 3. Пофайловый обзор (ключевое)

### `internal/domain` — ✅ без замечаний
- `user.go`: UserManager под RWMutex, все выдачи — копии значений; `BotID` хранится и в памяти, и в БД.
- `signal.go`: иммутабельные Snapshot() с глубокой копией `NotifiedChatIDs`; защита от out-of-order событий (`Timestamp.Before(OpenedAt)`).
- `config.go`: комиссии — потокобезопасная карта с клампингом [0; 1%], `FeeFor` с каскадом биржа→DEFAULT→встроенный ориентир 5 б.п.
- `ports.go`: опциональные интерфейсы (`SettingsRepository`, `StatsRepository`) — деградация без них корректна.

### `internal/app` — ✅ без замечаний
- `app.go` (698 строк): жизненный цикл Run/cleanup с дедлайнами изучен построчно; загрузка настроек при старте подтверждена живым прогоном; `/setfees`, `/stats`, `RouteBot` покрыты тестами.
- `sharded_aggregator.go`: 1024 шарда, O(E²) только по свежим котировкам (TTL 5с), prefilter объёма до дороги; **комиссии вычитаются до funding-оценки и порогов** — семантика «net» сквозная.
- `tracker.go`: один воркер (порядок OPEN/CLOSE важнее параллелизма), `ActiveCount()` под мьютексом.
- `funding_manager.go`: `lastUpdate` per-exchange для метрик; TTL-выселение + явный `SetStreamHealth(false)` при обрыве.
- `volume_engine.go`: retention 4ч+2м (окна >4ч не запрашиваются — проверено), проекция только по непрерывному ряду минут.
- `persistence_worker.go`: 4 воркера, backoff 200мс→5с, счётчик ошибок БД.
- `connector_manager.go`: `Count()`/`Names()` под RLock.

### `internal/ingress` / `retry` / `wsutil` — ✅ без замечаний
- Коалесцер: `stopped`-флаг исключает запись в закрытый канал; DrainAndStop не дедлокается на backpressure.
- Backoff: per-connection, полный джиттер [50%;100%] — штормы реконнектов исключены.
- Heartbeat: `WriteControl` безопасен параллельно с писателем данных.

### `internal/adapters/telegram` — ✅
- `bot.go`: один писатель на соединение (subscribes → потом keepalive), drop-метрики в обе стороны.
- `botpool.go`: маршрутизация по `users.bot_id`, fallback на первого бота, пустой пул — no-op (тесты покрывают).

### `internal/adapters/*` (биржи) — ⚠️ см. §5
Единый каркас добротный (backoff, дедлайны, `closeOnCtx`, `SetReadLimit`, фильтры BBO). Но живой прогон выявил **5 дефектов декодеров/подписок** и 2 гео-блока — детали ниже. Конкурентных записей в WS нет (проверено построчно: bingx — `writeMu`, остальные — подписки строго до старта keepalive-горутины).

### `cmd/screener` — ✅
slog, мульти-боты, стартовая проверка бирж (в smoke-прогонах корректно показала 451/403), сервер метрик.

### Инфраструктура — ✅/⚠️
- `Dockerfile` (multi-stage, scratch) ✅; `docker-compose.yml` (порт 9090, все env) ✅; `ci.yml` (vet/build/test/race/env-guard) ✅; `dev-setup.sh` (генерация пароля) ✅.
- ⚠️ `ARCHITECTURE.md` и `STRUCTURE.md` устарели (не описывают observability/botpool/settings/fees) — обновлены в этой ветке аудита.

## 4. Smoke-тест штатного режима (живой прогон)

Конфигурация: PostgreSQL 17 (локально), 8 коннекторов, noop-Telegram, метрики `:9090`, пользователь в БД, настройки в `settings` (hard_min_spread=0.012, fees DEFAULT:0.0006).

**Подтверждено живьём:**
- ✅ восстановление настроек из БД: `restored hard_min_spread from settings value=0.012`, `restored fees … DEFAULT:0.0006` — персистентность работает;
- ✅ загрузка пользователей из БД (1), клампинг их MinSpread к hard floor;
- ✅ конвейер: **444 500 тиков за 90с (~5 000/с)**, очереди `ticks/tracker_events/db_signals` — 0 (backpressure нет);
- ✅ `screener_db_errors_total = 0`, heap 122 МБ, 367 горутин;
- ✅ graceful shutdown **< 1 сек** (все коннекторы, persistence, router);
- ✅ `/healthz`, `/api/status`, `/metrics`, `/debug/pprof` отвечают.

## 5. Живое состояние бирж (главная находка)

Из IP песочницы (датацентр, регион заблокирован Binance/Bybit REST):

| Биржа | WS-коннект | Тики (90с) | Funding | Диагноз | Фикс кодом? |
|---|---|---|---|---|---|
| **BITGET** | ✅ | ✅ 362k (только SPOT) | ❌ (funding не приходит) | фильтр символов: поле `contractStatus` переименовано в `symbolStatus` → futures-подписка пустая | ✅ тривиальный |
| **KUCOIN** | ✅ | ✅ 82k (SPOT+FUT) | ❌ | `nextFundingRate` теперь **строка**, декод падает на каждом poll | ✅ тривиальный |
| **OKX** | ✅ | ❌ 0 | ⚠️ WS (age 17–43с) | подписка `tickers` **без instId** → биржа отвечает `error 60018`, код её молча игнорирует. Зонд: с instId тики идут | ✅ простой |
| **GATEIO** | ✅ | ❌ 0 | ✅ REST poll 10с | ① спот: `result` — **одиночный объект**, код ждёт массив → unmarshal-ошибка на каждом сообщении; ② фьючерсы: канал `futures.tickers` **не содержит bid/ask** вообще → нужен `futures.book_ticker` | ✅ средний |
| **MEXC** | ✅ | ❌ 0* | ✅ REST poll | ① `exchangeInfo.status` теперь **строка** `"1"` (код ждёт int) → списки символов не грузятся; ② *WS-подписки из этого IP отвечают «Blocked!» (WAF на датацентры) — на другом хостинге может работать | ✅ ① / 🌍 ② |
| **BINGX** | ✅ | ❌ 0 | ❌ | ① `/spot/v1/common/symbols`: `data` теперь **объект** `{"symbols":[…]}`, `status` — int; ② funding-эндпоинт требует `symbol` (код 109400) | ✅ средний |
| **BYBIT** | ✅ (WS жив!) | ❌ 0 | ❌ | REST 403 (CloudFront-геоблок) → список символов не грузится → WS-подписки нечем заполнять. **Зонд: сам WS stream.bybit.com из этого IP тикает** | ✅ кэш символов оживит |
| **BINANCE** | частично | ❌ 0 | ❌ | гео-блок 451 (REST) + bad handshake (spot WS); fstream коннектится, но пуша нет | 🌍 только регион/прокси |

Funding-возраст по метрике `screener_funding_age_seconds`: GATEIO ≈ 10с (poll) ✅, MEXC ≈ 0.1с (poll) ✅, OKX 17–43с (WS, нерегулярный пуш — **риск порога staleness 60с**), остальные −1 (нет данных).

**Дополнительная находка — MEXC funding цикл**: REST-поллинг 10 символов/сек × ~1 060 контрактов = полный цикл ≈ 106 секунд при `MaxDataStaleness = 60с` → записи протухают раньше переполлинга. Нужен per-exchange порог или ускорение поллинга.

## 6. Прочие находки

1. **Postgres-покрытие новых методов** (`GetSetting`/`SetSetting`/`SignalStats24h`) — нет интеграционных тестов (testcontainers есть только для Users/Signals/Reconcile).
2. **ARCHITECTURE.md / STRUCTURE.md** — не соответствовали коду (не описывали observability, BotPool, settings, комиссии) — обновлены в этой ветке.
3. **Дублирование фабрики коннекторов**: switch в `cmd/screener/main.go`, `cmd/smoke/main.go` и `internal/adapters/registry.go` — три места. Косметика, но при добавлении биржи легко забыть.
4. `Dockerfile` не декларирует `EXPOSE 9090` (compose мапит и так) — косметика.
5. Конкурентность/безопасность: подтверждены прежние выводы [04-concurrency-safety.md](04-concurrency-safety.md); новых рисков не найдено.
