## 2. P0 — Панель мониторинга (дашборд) — ✅ ГОТОВО, вариант A (08.09.2026)

**Реализовано** (`observability/` в репозитории): `prometheus.yml` (scrape app:9090 каждые 15с + self), `alerts.yml` (ScreenerDown, ExchangeSilent >5мин, FundingStale >120с, TelegramDropped >0/10мин, DbErrors >0/10мин), `grafana/provisioning/` (datasource + провайдер дашбордов), `grafana/dashboards/crypto-screener.json` (13 панелей: статы тиков/сигналов/дропов/ошибок, тики по биржам, funding age, сигналы, Telegram, очереди, алерт-лист, heap/goroutines) + сервисы `prometheus` (порт 9091) и `grafana` (порт 3000, анонимный Viewer) в `docker-compose.yml`. Запуск: `docker compose up -d prometheus grafana` → http://localhost:3000. Доставка алертов в Telegram — следующий шаг (нужен Alertmanager, см. P1).

**Сейчас есть** (без панели): `GET /metrics` (Prometheus), `GET /api/status` (JSON: очереди, активные сигналы, funding-возраст, доступность бирж), `GET /healthz`, `/debug/pprof`. Данные полные — визуального слоя нет.

**Рекомендуемый вариант A — Grafana + Prometheus (стандарт индустрии):**

```
docker-compose добавляет 2 сервиса:
  prometheus:  scrape http://app:9090/metrics каждые 5с
  grafana:     provisioning автоматом (datasource + дашборд из git)
```

Дашборд «crypto-screener Ops» (группы панелей):
1. **Поток данных**: `rate(screener_ticks_total[1m])` по биржам — мгновенно видно отвалившуюся биржу (панель станет нулевой);
2. **Коннекторы и funding**: `screener_connected_exchanges`, `screener_funding_age_seconds` (алерт: > 120с);
3. **Сигналы**: `screener_signals_opened_total` / `closed_total`, активные сейчас;
4. **Доставка**: `screener_telegram_sent_total` vs `screener_telegram_dropped_total` (алерт: дропы растут);
5. **Здоровье процесса**: goroutines, heap, GC, глубина очередей `screener_queue_depth`;
6. **Ошибки БД**: `screener_db_errors_total` (алерт: любое увеличение).

Алерты (без отдельного Alertmanager — grafana alerting в compose): «нет тиков от биржи N > 5 мин», «dropped > 0 за 10 мин», «funding_age > 120с», «db_errors > 0». Доставка — в тот же Telegram-бот.

Усилие: S (полдня) — compose-сервисы + `prometheus.yml` + `grafana/provisioning/*` + JSON дашборда, всё в git, ноль ручной настройки. Никакого кода Go.

**Альтернативный вариант B — встроенная HTML-страница `/dashboard`** в observability-сервере (авто-обновление fetch-ом `/api/status` и `/metrics`, без внешних зависимостей): легче деплой (один бинарник), но нет истории и алертов. Подходит как «быстрый взгляд», не как мониторинг.

Рекомендация: **A**, потому что вопрос стоит как «анализировать данные и видеть проблемы» — это история + алерты, а не только текущее состояние. Вариант B можно добавить позже как приятную мелочь.

## 3. P1 — Качество funding-данных

1. **Per-exchange `MaxDataStaleness`**: сейчас глобальные 60с. OKX WS шлёт funding нерегулярно (замер: 17–43с — на грани), MEXC REST-цикл ~106с — заведомо за порогом. Рецепт: `FundingConfig.StalenessByExchange map[string]time.Duration` c дефолтом 60с; MEXC 180с, OKX 180с. Funding-rate — медленные данные (ставка на 8ч), 60с — избыточно строго; обрывы детектируются отдельно через `SetStreamHealth`.
2. **Ускорить MEXC funding-поллинг**: сейчас 10 симв/сек последовательно. Варианты: параллельные воркеры (4×10), либо поллить только символы, реально встречающиеся в котировках (пересечение спот/фьючерс юниверса скринера).
3. **Кеш списка символов на диск** (TTL ~1ч): ускоряет рестарты, снижает rate-limit риск, и — главное — **оживляет Bybit** там, где REST гео-блокирован, а WS доступен (подтверждено зондом).

## 4. P1 — Тесты и CI

1. Интеграционные тесты (testcontainers) для `GetSetting`/`SetSetting`/`SignalStats24h` + `users.bot_id` round-trip — сейчас покрыто только юнит-тестами со стабом.
2. «Контрактные» тесты адаптеров на сохранённые живые payload'ы (файлы `testdata/*.json`): форматы бирж меняются без предупреждения — аудит это доказал; регресс-фиксация камней преткновения (OKX `nextFundingTime,string`, KuCoin string-rate, MEXC string-status, Bitget `symbolStatus`, Gate объект-vs-массив).
3. `golangci-lint` (минимальный набор: errcheck, govet, staticcheck) в CI.

## 5. P2 — Приятное и косметика

1. Единая фабрика коннекторов: `cmd/screener` и `cmd/smoke` дублируют switch — использовать `internal/adapters.NewByName` (регистр уже не важен).
2. `EXPOSE 9090` в Dockerfile.
3. Rate limit на команды Telegram per chatID (сейчас глобальный `commandMu`).
4. Дайджесты сигналов и приоритизация OPEN/CLOSE в очереди доставки (перенос из предыдущего плана).
5. `docker secrets` для продакшн-секретов.

## 6. Что по-прежнему НЕ делаем

- Backtest/реплей — отклонено владельцем (окончательно).
- Микросервисы, Kubernetes, ORM — см. анти-рекомендации [06-improvement-plan.md §12](06-improvement-plan.md).
- Egress-прокси для Binance — не раньше реального деплоя в заблокированном регионе (сначала пробуем разрешённый регион).
