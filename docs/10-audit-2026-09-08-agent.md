## 2. Найдено и исправлено (коммит `dd635be`)

### 2.1 🔴 KuCoin: гонка конкурентной записи в WebSocket — `readCandleShard`

`go kucoinKeepAlive(...)` (пишет `conn.WriteJSON(ping)`) запускался **до** цикла подписок
(тоже `conn.WriteJSON`). gorilla/websocket допускает только одного писателя на соединение
(исключение — `WriteControl`): пересечение фреймов пинга и subscribe способно испортить
фрейм и оборвать соединение; параллельный доступ к внутреннему буферу записи — data race.
Вероятность одного события мала (тикер ping vs короткий цикл подписок), но на 14+ шардах
и реконнектах неделями это стреляющая, а не теоретическая проблема. Остальные адаптеры
этот порядок соблюдают (MEXC/BingX — мьютексом, Bybit/OKX/Bitget/Gate — стартом keepalive
после подписок; `WriteControl` в wsutil безвреден by design).

**Фикс**: keepalive стартует после отправки всех подписок (симметрично `connectAndRead`).

### 2.2 🔴 MEXC: фатальные сбои при старте вместо retry — `ConnectFunding`/`ConnectFutures`

Единичный сбой REST в момент старта (список фьючерсных символов для funding-поллинга /
`contract/detail` для размеров контрактов) возвращал ошибку из Connect-метода —
connector-goroutine завершалась, и поток умирал **навсегда** (ConnectorManager не
перезапускает упавшие потоки; оживление только через `/rmex`+`/addex` или рестарт).
Все остальные адаптеры ретраят загрузку символов — MEXC был единственным исключением.

**Фикс**: загрузка символов/размеров контрактов ретраится с backoff (3с → 30с) до успеха
или отмены контекста. Контракт «быстрый выход по отменённому контексту» сохранён
(тест `TestMEXC_ConnectMethods_ReturnPromptlyOnCanceledContext`).

### 2.3 🟡 ShardedAggregator: утечка active-маршрутов при прекращении тиков — `Janitor`

Close-логика ProcessTick привязана к входящим тикам символа (`prefix := tick.Symbol + ":"`).
Если тики по символу прекращаются **совсем** (биржа удалена `/rmex`, делистинг, гео-блок
коннектора, смерть свечного/тикерного фида), close-цикл для этих маршрутов не выполняется
никогда: маршрут остаётся в `shard.active` бессрочно, а строка сигнала в PostgreSQL —
`is_active=TRUE` до рестарта процесса (ReconcileActiveSignals чистит только при старте).

**Фикс**: Janitor закрывает active-маршруты без наблюдений дольше `staleActiveRouteTTL`
(10 минут). События собираются под шардовым локом, отправляются строго вне лока (тот же
паттерн, что и ProcessTick). Конкурентные Janitor-ы не дают дублей (удаление из map под
локом — ровно один эмиттер закрытия; тест на 8 параллельных вызовов).

## 3. Проверено и подтверждено корректным

| Область | Вывод |
|---|---|
| **Порядки блокировок** | Единственное направление `shard.mu → {users.mu, funding.mu, volume.mu, config.mu}`; обратных захватов нет → ABBA-дедлок невозможен. ConnectorManager сериализует lifecycle отдельным `lifecycleMu`. |
| **Shutdown-цепочка** | Порядок StopAll(15с, параллельно) → DrainAndStop → close(tick-очередей) → FlushActive(бюджет 10с) → close(trackerChan) → close(dbChan) → persistWg(60с + grace) корректен; consumer раньше producer, send-on-closed исключён; `ingress.Forget` вызывается только при чистом StopAll (зомби-коннектор после таймаута безопасно игнорируется stopped-состоянием коалесера). |
| **Ingress-коалесер** | Ключ = сам канал; double-checked `stopped` под локом; `flush` re-put при отмене; DrainAndStop ждёт `runDone`. Утечки горутин нет. |
| **Кеш символов** | symbolscache: атомарная запись tmp+rename, глобальный мьютекс; Gate: 5-мин TTL под мьютексом; Bybit: REST → bytick → диск → seed. |
| **БД** | pgxpool 20/2 conns, lifetime 30м, idle 5м, healthcheck 30с, Ping при старте, схема идемпотентно; `rows.Err()` проверяется везде (молчаливые частичные чтения исключены); параметризованные запросы. |
| **Память** | Все растущие структуры ограничены: prices (TTL 60с, janitor), volume buckets (retention 4ч2м + janitor), ingress latest (clear при stop), active-маршруты (теперь TTL, см. 2.3), gzip-reader pool (Close→Put), очереди — буферизованные каналы с backpressure/таймаутами. |
| **Горутины** | Все фоновые горутины привязаны к ctx-cancel или close канала; таймеры останавливаются; `time.After` в циклах — только в bounded-циклах с короткими задержками (bybit подписочные батчи) — не утечка. |
| **Telegram** | Rate limit 25/с (ниже лимита TG), Retry-After 429, send-after-close исключён `sendMu` + `closed`; Close дренирует команды и очередь отправки. |
| **Форматы бирж** | Gate candle `n` = `"{interval}_{contract}"` (документация Gate.io WS v4) — `SplitN(n,"_",2)[1]` даёт корректный контракт; casing-ловушки sonic (e/E, b/B) везде закрыты явными полями. |
| **Ошибки/паники** | `NewTicker(0)` у KuCoin защищён fallback; nil-приёмники (Tracker, VolumeEngine, FundingManager) обрабатываются; входные данные валидируются до decimal-парсинга. |

## 4. Известные ограничения (не дефекты, решений не требуют)

- **Гео-блоки Binance/Bybit из датацентровых IP** — свойство окружения, не кода; зеркала/кэш/seed уже реализованы.
- **MEXC funding**: полный цикл поллинга ~500 символов при 10 симв/с ≈ 50с при бюджете свежести 60с — впритык, но в бюджете.
- **`/api/status` вызывает `runtime.ReadMemStats`** (короткая STW-пауза) — приемлемо для статус-эндпоинта, не скрейпится Prometheus.
- **Bybit/OKX/Bitget ConnectFutures ждут fundingReady**: если сконструировать ConnectorManager с nil fundingSink, futures-потоки не стартуют. В приложении fundingSink всегда передан — поведения продакшена не касается.
- **EscapeMarkdownV2 — заглушка**: parse_mode не используется, значит и не нужен.
