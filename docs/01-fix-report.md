## 2. Исправления ошибок компиляции (6)

### 2.1 `internal/wsutil/heartbeat.go` — неверное использование API
- **Проблема**: `if err := conn.SetPongHandler(...); err != nil` — в `gorilla/websocket v1.5.3` (это последняя версия, пути обновления нет) `SetPongHandler` **ничего не возвращает**.
- **Причина**: рефакторинг добавил heartbeat-модуль с ошибочным предположением о сигнатуре.
- **Исправление**: убран err-чек, оставлен прямой вызов.

### 2.2 `internal/app/notification_router.go:202` — повторное объявление переменной
- **Проблема**: `closed := nr.closed` объявляется второй раз в той же функции `ProcessSignal` (первый — на строке 160) → `no new variables on left side of :=`.
- **Исправление**: второе объявление заменено на присваивание `closed = nr.closed` (повторная проверка перед постановкой job в очередь — намерение сохранено).

### 2.3 `internal/adapters/bybit/bybit.go` — удалённые функции
- **Проблема**: код вызывает `toMarketTick(current, mType, eventTime)` и `go closeOnCtx(connCtx, conn)`, но обе функции были удалены при рефакторинге → `undefined`.
- **Исправление**: функции восстановлены. `toMarketTick` — в новой сигнатуре (3 параметра, `ts time.Time`), с полями `EventTime/ReceivedAt/Timestamp` (как у рабочих адаптеров bitget/binance) и валидацией `bid > ask` (защита от скрещённых котировок — соответствие архитектуре «executable spread»). `closeOnCtx` — в исходном виде из `309bb41`.

### 2.4 `internal/adapters/binance/binance.go` — три ошибки
- **Проблема 1+2**: два идентичных pong-хендлера (`conn.SetPongHandler(func(string) error {...})`) имели `return` только внутри `if` → `missing return` (замыкание обязано вернуть error).
- **Исправление**: добавлен `return nil` в оба хендлера.
- **Проблема 3**: в funding-ридере (строка 411) лог ошибки использовал несуществующую переменную `mType`.
- **Исправление**: заменена на литерал `"funding"` (консистентно с `keepAlive(connCtx, conn, "funding")`).

### 2.5 `internal/adapters/kucoin/kucoin.go` — отсутствующий импорт
- **Проблема**: код использует `sync.WaitGroup`, но импортирован только `sync/atomic`.
- **Исправление**: добавлен импорт `"sync"`.

### 2.6 `internal/adapters/okx/okx.go` — отсутствующие поля структуры
- **Проблема**: funding-ридер читает `d.FundingRate` и `d.NextFundingTime`, но структура `tickerData` этих полей не имеет (рефакторинг подключил funding-канал OKX, но забыл расширить структуру).
- **Исправление**: добавлены поля. Типы сверены с **живым API OKX** (REST-запрос `GET /api/v5/public/funding-rate`): `FundingRate string \`json:"fundingRate"\`` и `NextFundingTime int64 \`json:"nextFundingTime,string"\`` (OKX отдаёт время строкой миллисекунд — поэтому тег `,string`, по аналогии с существующим полем `Ts`).

## 3. Исправленные продакшн-баги (4)

> Это ошибки, которые **не мешали компиляции**, но ломали бы работу системы в бою.

### 3.1 🔴 `internal/adapters/mexc/proto.go` — декодер MEXC-клайнов не работал ВООБЩЕ
- **Проблема**: в `decodeMEXCSpotKline` оператор `switch wire { case 0: ... case 2: skip ... case 1: ... case 3,4: ... case 308: ... }` смешивал **wire types** (0=varint, 2=bytes) и **номера полей** (1, 3, 308) в одном переключателе. Поле 308 (`publicSpotKline`, wire type 2) всегда попадало в `case 2` («пропустить») и никогда не читалось. Также пропускались поля 1 (channel) и 3 (symbol).
- **Последствие**: ни один MEXC-клайн никогда не декодировался бы → volume-фильтры по таймфреймам для MEXC молча не работали.
- **Исправление**: switch реструктурирован в два уровня — сначала по wire type (0, 2, 1=fixed64, 5=fixed32), внутри wire type 2 — по номерам полей (1, 3–4, 308, default=skip). Это классическая ошибка ручного парсинга protobuf.

### 3.2 🔴 `internal/app/funding_manager.go` — свежие funding-данные считались устаревшими
- **Проблема**: `IsStale` содержал правило `age < 0 → stale`, где `age = now − LocalReceivedAt`. Но в продакшне `now` берётся из **тика** (`tick.ReceivedAt`, см. `sharded_aggregator.go:125`), а `LocalReceivedAt` — время получения funding-апдейта. Если funding пришёл на 10 мс **позже** тика (нормальная ситуация), age отрицателен → все сигналы блокировались с `DATA_STALE`.
- **Последствие**: при активном funding-потоке screener **молча отбрасывал бы все арбитражные сигналы** — самый опасный тип бага (система выглядит живой, но не делает свою работу).
- **Исправление**: правило `age < 0` удалено; устареванием считается только реальный возраст `age > max`.

### 3.3 🟡 `internal/app/app.go` — админ-команды требовали подписки
- **Проблема**: проверка «Вы не подписаны» выполнялась раньше обработки команд, при этом `sethardspread`/`addex`/`rmex` доступны только админам — администратор, не подписавшийся через `/start`, не мог ими пользоваться.
- **Исправление**: введён флаг `isAdminCmd`; для админ-команд проверка подписки пропускается (безопасно — админ-ветки не используют объект `user`).

### 3.4 🟡 `internal/adapters/telegram/bot.go` — блокирующая отправка и недренаженный канал
- **Проблема**: `SendPrivateMessage`/`Broadcast` блокировались до 5 секунд при полной очереди (Broadcast — по 5с на каждого получателя!). `Close()` закрывал `sendChan`, не очистив буфер.
- **Исправление** (возврат к семантике исходного дизайна `309bb41`, подтверждённой тестами): неблокирующая отправка со сбросом при полной очереди + дренаж `sendChan` в `Close()` перед закрытием. Безопасность от send-on-closed сохранена через `sendMu` + флаг `closed`.
